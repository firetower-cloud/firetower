Ordered by how much the design leans on each one, highest first — those are the ones reuse depends on. The counts are measured by walking the redesign artifact: 50 screens, every view and every overlay. Specimens are isolated in shadow roots, so the redesign's class names cannot collide with this page's.

The duplication is the bug

desktop/src/components/ui/ and web/components/ui/ ship eleven identically named components. Ten are byte-identical. List.tsx differs by exactly one line — its Link import — which is the shim mechanism working as designed. Only Brand.tsx has genuinely diverged: 176 lines against 22.

So the problem is not that two drifted. It is that eleven are duplicated at all — ten of them identically, kept in step by nothing but discipline, which is exactly what docs/which-surface.md says the answer is not. Ten identical copies are ten chances for the eleventh edit to land in one file only. Brand.tsx is what that looks like afterwards: web carries GithubMark alone, so it cannot draw a GitLab or Gitea mark at all.

Patterns6

Shapes that recur and are re-implemented each time. This is where reuse is actually lost — nothing is obviously wrong with any single screen. Rendered as miniatures, because a pattern described in prose is exactly the thing that gets built again.

List page

25 of 50 instantiated on

A title, one sentence, one action, then rows. Eleven configuration screens are this shape and each currently re-implements it.

bits.tsx has Section and Rows, which is two thirds of it. The missing third is the page head and the single action.

Create menu

7 of 50 instantiated on

“Make one” that offers how — by hand, or by asking an agent.

config/CreateMenu.tsx already exists and is used twice (Skills, Profiles). Every other Add on every other screen is a plain button. Audit each one: it either belongs to this pattern or has a reason not to.

Picker sheet

18 of 50 instantiated on

Choose from a list, inside a sheet: find, rows, a tick, a footer that commits.

Used by repository, machine, profile, skill, agent, scope and tracker pickers. Seven screens, one shape, no shared component today.

Refusal dialog

42 of 50 instantiated on

Something will not work, and the thing to do is elsewhere.

The five dictation dialogs are the only ones built this way. The Gate, the limit hand-off and several error states are the same idea drawn differently.

State set

10 of 50 instantiated on

Empty · loading · error · denied · server dark. A fresh install hits every one of these at once, so none is an edge case.

Every list needs all five. Rows in bits.tsx does three.

Where-this-lives note

15 of 50 instantiated on

A line saying what this screen does not do, and where it is done instead.

People, Teams, Account and Repositories each end with one. It is how the read-only surfaces stay generous instead of looking withheld.

Already solved on web — stop redrawing4

  • Checkbox — Needed by Skills’ multi-select, which is a gap on Coverage. Ships on web; absent on desktop.
  • Menu — Desktop has Pop; web has Menu. Two implementations of one idea — pick one before a third appears.
  • Table — The Spec and Coverage tabs of the redesign are tables. Nothing on desktop uses a table component because there is not one.
  • QrCode — Not needed by any desktop screen in this design. Listed so the next person does not add a second one.
