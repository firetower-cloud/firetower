What Start should do

A task’s Start button points at nothing in particular. Four propositions for what it should point at instead, drawn at 1280 in both themes — and one finding that matters more than any of them: the thing the user is asking for is half a server change.

What happens today

desktop/src/start.tsx is deliberately one path for every caller. Its own header says they “mean the same thing and differ only in how much they already know”, and that routing them through one place “is what keeps a task’s Start one click rather than a second form that happens to look similar.” start(seed) stashes what the caller knows in a module variable, navigates, and the destination reads it once — because a hash route carries no state.

It navigates to /new. We merged /new into the home, and Routes.tsx:30 now answers that path with <Home>. So Start lands you on the Dashboard with a seeded composer. That is the whole complaint, and it is accurate: you asked to start one specific thing and arrived somewhere general.

It is seven callers, not three. useStart is called from Rail.tsx:39, RailPanel.tsx:219, TasksPage.tsx:100, ArtifactsPage.tsx:51, config/Roles.tsx:107 and config/Skills.tsx:59 — and Palette.tsx:75 navigates to /new directly, so ⌘K → New workspace carries no seed at all and already behaves differently from ⌘N. Four of those six seed only a prompt string (“Make me an artifact that ”). Only the task seeds a repository. That asymmetry decides most of what follows: a chooser that is right for a task is wrong for Create with AI, which has nothing to choose between.

What the server can actually do

This is the part that changes the brief. There are three ways a session comes into being, and a person can reach only two of them.

A new workspacePerson can — POST /sessions with repoId, prompt, taskKey, taskUrl. This is what Start does today.
Another agent in an existing workspacePerson can — NewSession.workspaceId, already wired as useStartAgent() in components/workspace/StartAgent.tsx:89. But it makes a sibling, not a child: no parent_id, no spawn_reason, and its hand-back goes to your inbox rather than into the lead’s conversation.
A child under a running leadPerson cannot — sessions.parent_id is written only by delegate::serve, reached from the agent’s own spawn tool over AgentAsks. NewSession has no parentId field. delegation.md is explicit: null for every session a person started, which is every session there was.
A lead that builds its own teamPerson can — NewSession.profile, which “decides whether this session may delegate — a Manager may, an Operator does the work itself.” A profile with a team leads; without one it is a worker (config/Roles.tsx).
So “hand this task to the lead already running” has exactly two honest implementations. Either the desktop sends a message into that lead’s conversation — “take on NW-4120: …” — and the lead calls spawn itself, deciding placement; or NewSession grows parentId and spawnReason and the desktop makes the child directly. The first ships today and is a request, not a command. The second is a small, well-shaped addition — delegate.rs already does exactly this through the same create_session_as the API uses — and it is the one I would ask for. Drawing a “create a sub-workspace” control before it exists would be drawing a control the server will not honour, which which-surface.md names as the same mistake as sending a member to a screen that will refuse them.

One limit still shapes the drawing: a child cannot spawn. So a lead that is itself a child cannot be handed anything. delegation.md has since dropped the caps on how many children a lead may start, so there is no “at capacity” state to draw — which removes a refusal the first version of this document had.

1 · Start just starts Recommended, as the floor

Start creates the workspace and lands you in it. No intermediate screen, no seeded composer to confirm: the repository came from the task, the branch is derived from its key, and the agent is already reading. The seeding becomes invisible, which is what seeding is for.

Good at

The common case, which is also the stated contract: one click. It is the only proposition that makes Start faster than today rather than slower. The task link and branch ride along in the composer footer, so what it did is legible after the fact.

Costs

It commits. There is no moment to change the repository, the branch or the agent, and no way to reach delegation at all — so on its own it does not answer the user’s question, it only fixes the landing. It also removes the one screen where a mis-detected repository could be corrected.

When the answer is missing

No repository on the task (NW-4099): there is nothing to cut a branch from, so it must fall back to the seeded composer — today’s behaviour, now as the exception rather than the rule. Repository not checked out anywhere: the workspace is still valid; the checkout is what the machine picker is for, and that is the one case that has to ask.

2 · Start opens a small anchored sheet

Start becomes a question with two or three answers, anchored to the row that asked it. Pressing ↵ takes the first, so the common case stays one keystroke even though it is two clicks.

And the same control on NW-4101, whose repository has nothing running on it — the second answer stays listed and says why, which is the rule StartAgent.tsx already follows: “vanishing from a menu looks like the thing does not exist and leaves nowhere to learn what is missing.”

Good at

It is the only shape that teaches that delegation exists. Most people do not know a running lead can be handed work; a menu that lists it once is how they find out. It also scales: start as a manager is a third answer with nowhere else to live.

Costs

Two clicks on the common case, against the one thing start.tsx exists to protect. And it is wrong for the other six callers: Create with AI from Skills has no repository and no lead, so the sheet would offer one live answer and two dead ones.

When the answer is missing

Dead entries stay and say why, as drawn. With no repository, hand to a lead and new workspace on this repository are both unavailable and the sheet collapses to one live answer — at which point it should not open at all, which is a rule worth writing down rather than a state worth drawing.

3 · A split control Recommended

The button does proposition 1. The caret beside it opens proposition 2. The common case is one click and the second intention is one click away, which is the whole disagreement resolved by spending 14px of row.

The caret opens the same anchored sheet, so there is one menu to design and one to maintain:

Good at

It keeps the contract start.tsx was written to keep and still surfaces delegation. It is also the only proposition that survives the seven-caller constraint: the caret is drawn only where there is more than one answer, so the rail’s +, ⌘N and Create with AI keep a plain button and nothing about them changes.

Costs

Two targets 14px apart on a row people click quickly, and the quiet half is the one that does something irreversible. It needs a real keyboard story — ↵ starts, ↓ or ⌥↵ opens — or it is a mouse-only feature on a list that is otherwise fully navigable.

When the answer is missing

The caret disappears and the button stays. On NW-4099 there is no repository, so there is nothing to delegate and nothing to choose: it degrades exactly to proposition 1. This is the reason to prefer it — the degenerate case is not a special case, it is the floor.

4 · Drag the task onto a workspace Would not ship

The row itself becomes the thing you move. Drop it on empty space and it is a new workspace; drop it on a running lead and it is handed there. The panel shows where it would land.

And where it lands — the task arrives as a child under its lead, indented in the rail, which is exactly how delegation.md says a child in its own workspace is drawn:

Good at

It is the only one where the destination is visible while you choose it — you can see that Ada is already in northwind/api and has two children, which is the fact that makes delegating the right call. Nothing else shows you that at the moment of deciding.

Costs

Undiscoverable, with no affordance until you already know. No keyboard equivalent exists and inventing one is inventing a second interaction. It needs the panel open, which is a ⌘\\ away. And it cannot be the only path, so it is always a second path — more surface for the same job.

When the answer is missing

Everything becomes an invalid drop target with no explanation, which is the worst version of a missing answer: the gesture simply does nothing and the row snaps back. A menu can say nothing is running on this repository; a drop target cannot.

What I would do

Ship 3, which is 1 with a caret. Make the button do the right thing — create and land you in it — and hang the second intention off a caret that is only drawn when there is a second intention. That keeps one click, keeps one start() path, and leaves the six callers with nothing to choose entirely unchanged.

Ship 1 first, on its own. It is most of the value, it is a small change, and it is correct whatever happens to delegation. The caret can follow when the server can honour it.

Do not ship 4. It is the most pleasing of the four and the least defensible: undiscoverable, mouse-only, and it fails silently in exactly the cases that need an explanation.

Ask for parentId on POST /sessions. Until then, hand to a lead has to be drawn as what it would actually be — a message into that lead’s conversation, which the lead may act on when it finishes its turn. That is a defensible feature and an honest label, but it is not the one the user is picturing, and the difference should be their call rather than a silent substitution.

Mobile

which-surface.md: mobile reads and starts work. It writes no access of any kind. Starting is explicitly in scope, so proposition 1 belongs on the phone. Delegation is not access — it creates a session, not a grant — so the rule does not exclude it; what excludes it is that the caret and the anchored sheet are both pointer shapes on a surface that has no hover. If delegation goes to the phone it wants the ⋯ menu StartAgent.tsx’s header already says the phone grew, not a caret.
